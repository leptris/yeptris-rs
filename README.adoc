= yeptris-rs

Rust bindings for link:https://github.com/leptris/yeptris[libyeptris], the pure
C11 YAML 1.2 parser with a document arena, zero-copy value views, and a
byte-stable emitter — zero required runtime dependencies.

This repository owns the publishable `yeptris` crate. It is the standalone
binding repository for the engine — the same model as the
link:https://github.com/leptris/leptris-rs[leptris-rs],
link:https://github.com/leptris/yeptris-ruby[yeptris-ruby], and
link:https://github.com/leptris/yeptris-py[yeptris-py] bindings: one engine,
many binding repositories, each with its own CI and releases.

Part of the yeptris program: *the best (multiple dimensions)
YAML/JSON parser/builder ever* — conformance, performance,
safety/hardening, API surfaces, transport correctness, and trust,
held simultaneously, in C, Ruby, Rust, and JS. This binding is the
thin safe Rust surface. The event face (the engine's pull model as a
Rust `Iterator`) and the serde bridge are in; the recorder's bulk
drain and the lazy per-document stream are the follow-ups (the
engine's PLAN.md, "The best-ever program").

== Usage

[source,rust]
----
use yeptris::Document;

let doc = Document::parse(b"name: yeptris\nlangs: [c, rust]\n").unwrap();
let root = doc.first_root().unwrap();
assert_eq!(root.get("name").unwrap().str(), Some("yeptris"));
assert_eq!(root.get("langs").unwrap().items().count(), 2);
----

The C library is resolved at link time: set `YEPTRIS_LIB_PATH` (see
`build.rs`) or install libyeptris on the library path. CI builds the engine
from source and exports the variable.

=== serde

The default `serde` feature gives the `serde_yaml`-shaped surface over the
same engine — `Value` (insertion-ordered mappings, `Tagged`, core-schema
scalar resolution), `from_str`/`from_slice`/`from_value`, `to_string`
(engine emitter via the bulk build API), and `to_value` for any
`Serialize` type. serde_yaml is archived; this is the drop-in seat.

[source,rust]
----
use serde::{Deserialize, Serialize};
use yeptris::{from_str, to_string};

#[derive(Serialize, Deserialize)]
struct Config { name: String, port: u16 }

let cfg: Config = from_str("name: engine\nport: 8080\n").unwrap();
let yaml = to_string(&yeptris::to_value(&cfg).unwrap()).unwrap();
----

Two deliberate, documented divergences from serde_yaml/Psych, both
YAML-1.2-spec positions: `<<` stays a literal mapping key (the spec
removed merge keys; the engine's core-12 default), and a tag is
preserved for `Value` but rejected by non-enum typed visitors (the
serde_yaml contract). Build with `default-features = false` for the
zero-dependency DOM-only crate.

=== streams

`parse_stream` is the multi-document face at ruby/py parity
(`load_stream` / `load_all`): every document in the stream, in order,
as an eager `Vec<Value>`.

[source,rust]
----
use yeptris::{parse_stream, Value};

// the boundary law: a content-less document rides its boundary as
// Value::Null (ruby's nil, py's None); a document-less stream is an
// empty vec; a malformed document fails with the engine's position
assert_eq!(
    parse_stream(b"---\nfoo\n---\n").unwrap(),
    vec![Value::String("foo".into()), Value::Null]
);
----

=== events

`yeptris::event::Puller` wraps the engine's pull model (events.h, the
StAX-style cursor): one `next()` is one `yeptris_pull_next` call — no
buffering, no allocation beyond the event view.

[source,rust]
----
use yeptris::event::Puller;
use yeptris::event::EventKind::*;

let mut puller = Puller::new(b"a: 1\n---\nb: 2\n").unwrap();
for ev in puller.events() {
    let ev = ev?;
    // kind(), value(), anchor(), tag(), line()/col() .. end marks
}
----

== Mapping to the C engine

The crate is a binding, not a reimplementation. Rust types map onto the
engine's opaque handles (`YeptrisDocument`, `YeptrisNode`) and every
operation is a thin safe wrapper over the corresponding `yeptris_*` C
function. The ownership contracts become types:

* `Document<'input>` — the engine's value views are zero-copy slices INTO
  the parsed buffer, so the document cannot outlive the bytes it parsed.
  Dropping the `Document` frees the engine's arena in one call.
* `Node<'doc>` — a borrowed view; `value()`/`str()`/`tag()`/`anchor()`
  return zero-copy slices or UTF-8 strs with the document's lifetime.
* `Error` mirrors `YeptrisStatus` one-to-one; messages (with line/column)
  come from the engine's thread-local error channel.

Scalar styles (`Style`), node kinds (`NodeKind`), anchors/aliases (with
`alias_target`), tags, and multi-document streams (`---`) are all surfaced.

== Development

[source,bash]
----
cmake -B engine/build-shared -S /path/to/yeptris \
  -DCMAKE_BUILD_TYPE=Release -DYEPTRIS_BUILD_SHARED=ON \
  -DBUILD_TESTING=OFF -DYEPTRIS_BUILD_CLI=OFF -DYEPTRIS_BUILD_BENCHMARKS=OFF
cmake --build engine/build-shared
YEPTRIS_LIB_PATH=$PWD/engine/build-shared/src cargo test
----

CI runs the same flow on ubuntu and macOS (`cargo build`, `cargo test`,
`cargo fmt --check`).

== Versioning

The crate versions in lockstep with the engine's minor lines (the
yeptris-ruby model): 0.6.0 is the first engine-0.6-ABI-tagged cut
(engine v0.6.30); the binding's major.minor tracks the engine ABI it
binds, and the patch tracks the binding itself.
